# ReasonTree

**Reasoning-based document retrieval using hierarchical tree indexing.**

ReasonTree builds a structured, semantic tree from long documents and uses language model reasoning to navigate that tree during retrieval. There are no vector databases, no chunk boundaries, and no approximate similarity matching. When you ask a question, the system reasons over the document hierarchy the same way a subject-matter expert would flip through a technical manual: by understanding structure, context, and intent.

The project began as a study of why vector-based RAG consistently underperforms on professional documents, and grew into a working retrieval framework that treats document structure as a first-class citizen.

---

## Why This Exists

Vector similarity search has a fundamental mismatch with professional documents. A question about a risk factor buried in a 10-K filing may share almost no surface-level vocabulary with the answer, yet a trained analyst would find it immediately because they understand how annual reports are organized. The analyst does not retrieve by similarity; they retrieve by reasoning.

ReasonTree approaches retrieval the same way. It first builds a tree of the document, section by section, with each node carrying a title, page range, and a short summary. Then, when a query arrives, it walks that tree using an LLM as the navigator, pruning branches that are irrelevant and drilling into the ones that are not. The result is a set of source pages with an auditable decision trail.

---

## How It Works

**Step 1 - Build the index.** ReasonTree reads a PDF or Markdown file and generates a hierarchical tree where each node represents a document section. Nodes include the section title, start and end page numbers, and an optional summary generated by the LLM. The tree mirrors the document's natural organization rather than imposing arbitrary chunk sizes.

**Step 2 - Run a query.** The retrieval engine receives a query plus optional context (conversation history, prior answers, domain notes). It traverses the tree from the root, asking the LLM at each branch which subtrees are worth exploring. This is tree search guided by reasoning, not lookup by vector distance.

**Step 3 - Return pages.** The engine returns the specific pages the LLM decided were relevant, along with the reasoning it used to get there. You can inspect exactly which nodes were visited, which were pruned, and why.

## Quick Start

### Requirements

- Python 3.10 or higher
- An OpenAI API key (or any LiteLLM-compatible provider)

### Install

```bash
git clone https://github.com/sunilgentyala/ReasonTree.git
cd ReasonTree
pip install -e .
```

Or install dependencies directly:

```bash
pip install -r requirements.txt
```

### Set your API key

```bash
export OPENAI_API_KEY=your_key_here
```

Or create a `.env` file in the project root:

```
OPENAI_API_KEY=your_key_here
```

### Index a document

```bash
python -m reasontree index --input /path/to/document.pdf
```

The tree structure is saved to `./results/<document_name>_tree.json`.

### Run a query

```bash
python -m reasontree retrieve \
  --index ./results/document_tree.json \
  --query "What are the main risk factors?"
```

### Use the Python API

```python
from reasontree import ReasonTreeClient

client = ReasonTreeClient(api_key="your_key")

# Index a document once
doc_id = client.index("annual_report.pdf")

# Run queries against it
result = client.retrieve(doc_id, "What was the revenue growth in Q3?")

print(result.pages)      # list of page numbers retrieved
print(result.reasoning)  # the path the LLM took through the tree
print(result.content)    # extracted text from those pages
```

## Configuration

ReasonTree reads its defaults from `src/reasontree/config.yaml`. All values can be overridden at the command line or when constructing the client.

| Parameter | Default | Description |
|---|---|---|
| `model` | `gpt-4o-2024-11-20` | LLM used for indexing |
| `retrieve_model` | same as `model` | LLM used for retrieval (can differ) |
| `toc_check_pages` | 20 | Pages scanned for an existing TOC |
| `max_pages_per_node` | 10 | Maximum page span per tree node |
| `max_tokens_per_node` | 20000 | Token ceiling per node during indexing |
| `add_node_summary` | true | Generate summaries for each node |
| `add_node_id` | true | Assign stable IDs to nodes |

See `docs/configuration.md` for the full reference.

## Multi-provider Support

ReasonTree routes all LLM calls through LiteLLM, so you can use any supported provider. Set the appropriate environment variable and pass the model name in LiteLLM format:

```bash
ANTHROPIC_API_KEY=your_key python -m reasontree index \
  --input document.pdf \
  --model anthropic/claude-opus-4-7
```

## Benchmark Results

On the FinanceBench dataset (150 financial QA questions over SEC filings), ReasonTree's tree-search retrieval consistently outperforms flat vector search, particularly on multi-hop questions that require understanding document structure rather than surface-level keyword matching.

Full numbers, methodology, and comparison scripts are in `artifacts/benchmarks/`.
